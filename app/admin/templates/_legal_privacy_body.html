What is processed

  • Account: username, optional email, password hash (bcrypt) — never plaintext passwords.
  • API keys: label, SHA-256 hash, prefix. The full key is shown once at creation.
  • Usage metadata: time, service, path, model name, result (ok/deny/429), duration, optional token/audio estimates, key label.
  • Not stored: prompts, chat messages, embedding text, STT/TTS audio, response bodies.
  • Client IP: {% if auth is defined and auth and auth.anonymize_client_ip %}anonymized (last octet / IPv6 truncated){% else %}stored as received when logging is on{% endif %}.

Purposes and legal bases

Operating the gateway, sign-in, access control, and quotas. Legal bases: GDPR Art. 6(1)(b) (contract / use of the service) and Art. 6(1)(f) (legitimate interest in a secure operation).

Retention

Accounts and keys stay until deleted. Usage events: {% if auth is defined and auth and auth.retention_days %} purged automatically after {{ auth.retention_days }} days. {% else %} no automatic purge (operator setting). {% endif %} Signed-in users can wipe their own usage under Data & Privacy.
